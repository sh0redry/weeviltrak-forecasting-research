# 问题1验证方案

## 背景

针对 `docs/investigations/stage1_prediction_issues.md` 中的问题 1，之前的验证思路是：

- 使用 `2026-03-01` 之前的数据训练
- 对固定时间窗口内的大量空间网格点做预测
- 观察预测值是否收敛到 0

在实际讨论后，确认这种方式存在两个问题：

1. 预测地点过多，运行时间过长
2. 固定日历窗口不一定覆盖每个地点真实的 Stage 1 发生时间，因此“是否到 0”未必有验证意义

因此，问题 1 的验证方案调整为：只在有历史 weevil 数据的地点上，围绕真实 Stage 1 发生日期构建预测窗口，并观察预测值是否收敛。

## 训练窗口

- 验证训练方式采用 **5 年滑动窗口**
- 对每个测试年份 `Y`：
  - 训练仅使用 `stage_date < Y-03-01`
  - 训练样本限制在 `[Y-03-01 往前推 5 年, Y-03-01)` 这个范围内

这样做的目的：

- 保留最近几年对当前天气与业务模式更相关的数据
- 避免过老年份数据对 Stage 1 行为的干扰

## 新验证原则

- 不再使用大量 `place_id` 空间网格作为主验证对象
- 地点来源只使用 `pull_weevil_data()` 中的历史地点
- 每条线对应一个 `location_id`
- 只验证 `Stage 1`
- 对每个地点，不使用固定日历日期窗口
- 改为围绕该地点真实 `stage_date` 构建验证窗口

## 地点来源

地点来源规则固定为：

- 只使用 `pull_weevil_data()` 中已有历史记录的 `location_id`
- 不再从 `spatial_coverage.csv` 全量筛选验证地点
- 不再以 `place_id` 作为主验证粒度

说明：

- `spatial_coverage.csv` 仍可用于辅助映射或天气数据准备
- 但验证图和验证结果的主对象改为历史监测点 `location_id`

## 时间窗定义

对每个有历史 Stage 1 记录的地点：

- 使用该地点真实的 `stage_date` 作为中心
- 验证窗口定义为：

`prediction_date ∈ [stage_date - 3天, stage_date + 3天]`

即：

- 事件前 3 天
- 事件当天
- 事件后 3 天
- 共 7 天

## 验证目标

在上述窗口内，验证分成两个业务目标：

### 目标1：是否终止

观察业务输出 `predicted_days` 的行为：

- 是否在事件附近 7 天内总体下降
- 是否在接近 `stage_date` 时收敛到 0
- 是否在事件后 `+1` 到 `+3` 天内仍持续保持正值

### 目标2：预测是否准确

观察模型给出的 `predicted_stage_date` 与真实 `stage_date` 的差值：

- 不是只看“终止的那一天”
- 而是看整个 `[-3, +3]` 窗口内给出的预测日期是否接近真实日期
- 汇总时重点关注 `days_from_event ∈ {-1, 0, +1}` 这 3 个最接近业务判断点的位置
- 核心误差定义：

`error_days = predicted_stage_date - actual_stage_date`

后续输出时可同时汇总：

- `error_days`
- `abs_error_days`

说明：

- 这里关注的是业务输出 `predicted_days`
- 不以原始负值输出作为主验证图展示对象
- 图中仍保留 `y = 0` 参考线

## 图形展示

图形展示方式调整为：

- 每个测试年份单独输出结果
- 每个测试年份输出两张图

### 图1：收敛轨迹图

- 每条线对应一个 `location_id`
- 横轴使用 `days_from_event`
- 纵轴使用业务输出 `predicted_days`
- 图中加入 `y = 0` 参考线
- 用于直观看“是否终止”

### 图2：误差分布图

- 使用 `error_days = predicted_stage_date - actual_stage_date`
- 每个测试年份单独输出误差分布图
- 用于直观看“预测偏早还是偏晚”
- 可同时辅助观察误差分散程度

其中横轴定义为：

`days_from_event = prediction_date - stage_date`

因此图1的横轴范围固定为：

- `-3` 到 `+3`

这样同一年内不同地点可以在同一参考系下比较收敛行为。

## 当前结论

问题 1 的后续验证不再采用“固定 3/1-3/24 + 全量空间网格”的方式。

改为采用：

- 历史地点 `location_id`
- 真实 Stage 1 日期对齐
- `stage_date - 3` 到 `stage_date + 3` 的验证窗口
- 横轴使用 `days_from_event`

后续若需要扩展到不同年份的训练/测试切分，再在本方案基础上继续细化。
